Title: Heap overflow in the thumbnail decoder reachable from untrusted input

Summary
-------
A malformed JPEG embedded in a document preview can overflow a fixed 4096-byte
stack buffer in parse_thumbnail(). The length field is read from the file and
used directly as a memcpy size without validation against the destination.
Reproduced on builds 7.2.1 through 7.4.0 on Linux and Windows.

Reporter contact: Dana Whitfield, dana.whitfield@example-research.org, +1 555 0142.
The proof of concept was shared privately with the vendor on 3 March.

Steps to reproduce
------------------
1. Build the attached poc.jpg, which declares a thumbnail length of 0xFFF0.
2. Open it with `previewd --render poc.jpg`.
3. The process aborts with a stack smashing message, or silently corrupts the
   return address when hardening is disabled.

Impact
------
An attacker who can supply a document to a preview service gains control of the
saved return address. On the affected internal deployment this reaches the
document ingestion tier, which runs as service account svc-preview-prod and has
read access to the customer artefact bucket. Escalation from there to the
signing infrastructure was not investigated.

Affected customer: Northwind Traders, tenant 4d9f-2211, notified 5 March.

Suggested fix
-------------
Clamp the declared thumbnail length to the remaining input size before the copy
and reject frames whose declared length exceeds the buffer. A minimal patch is
attached as thumbnail-bounds.patch.
